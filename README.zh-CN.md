# VIR Signals

[English](README.md) | [简体中文](README.zh-CN.md)

源码仓：[VIR-signals/vir-signals](https://github.com/VIR-signals/vir-signals)

VIR Signals 用所选语音包的音频替换 VS Code 的内置音效文件。编辑器的信号系统不变，播放的信号不变，声音来自所选语音包。扩展内置演示语音包；语音包可从索引仓库安装，携带规范清单的本地音频文件夹亦可作为语音包使用。

**功能**

- **替换** —— 语音包音频按槽位替换官方音效文件；槽位由语音包清单声明。
- **语音包来源** —— 内置演示语音包、索引仓库条目、本地语音包目录。
- **信号开关** —— 信号可逐个启用或停用，替换可整体暂停。
- **备份与还原** —— 官方音效文件在变更前备份，可单条命令还原，卸载扩展时自动还原。

> **使用前必读：本扩展会写入编辑器安装目录。** 它用语音包中的音频替换 VS Code 的内置音效文件。官方文件的完整备份会自动建立，可通过单条命令恢复，并在扩展卸载时自动还原。并非所有安装形态都受支持：Microsoft Store 版、Windows 系统级安装以及只读包格式会被识别并以明确信息拒绝。

## 工作原理

- 编辑器官方音效文件位于安装目录内一个带版本号的文件夹中。扩展定位该文件夹，备份其中全部文件，然后将所选语音包的音频替换进去。
- 替换完成后，必须完全重启编辑器，所有信号才会采用新音频。每次替换流程结束时会有独立的警告通知予以提示。
- 编辑器自我更新后，新的官方文件会被重新备份，当前生效的语音包会自动铺设到新文件之上。

## 快速上手

1. 首次启动时，扩展执行官方音效文件的初始备份，并请求重载一次窗口，使扩展的命令名称跟随编辑器显示语言。
2. 重载后，扩展引导进行语音包选择。选择列表包含扩展内置的 demo 包、索引仓库收录的语音包，以及全部本地语音包。
3. 选中语音包后立即应用。结果通知提供两种信号开关模式，流程最后以一条独立警告通知收尾：必须完全重启编辑器，所有信号才会采用替换后的音频。

## 卸载

在编辑器中对本扩展执行「禁用」之前，先运行 **VIR: Toggle Sound Replacement** 还原官方文件：被禁用的扩展无法执行任何还原操作，仅剩卸载钩子仍会运行。

卸载扩展时，官方音效文件自动还原，扩展切换过的每项信号设置恢复原值。还原在卸载后 VS Code 下一次启动时执行（编辑器将卸载处理，包括本次还原，延迟至下次启动），在此之前当前音效保持不变。文件还原优先使用扩展目录内的快照，其次使用扩展存储中的备份；两者均缺失时不做任何猜测，保持原状。

## 语音包

选择列表（**VIR: Select Voice Pack**，亦可点击状态栏铃铛进入）包含以下几类条目。恰好一行带有对勾，标记当前生效的语音包；索引条目版本高于本地已装副本时，以升级箭头标记。

- **索引条目** —— 发布在索引仓库中的语音包，显示版本、语言与槽位覆盖。选中后提供 **Preview**（试听）与 **Install or Update**（安装或更新）。
- **本地语音包** —— 语音包目录中的文件夹。选中后立即应用。
- **不启用** —— 还原并保持编辑器官方音效。
- **从仓库地址直装** —— 接受 `owner/repo` 形式（可附包路径），不经过索引、直接从任意仓库安装。

**Preview（试听）** 打开试听面板：完整语音包下载至专用临时目录（绝不写入语音包目录），全部槽位连同触发它们的系统事件一并列出，点击已覆盖行即播放对应音频。关闭面板即删除该临时目录。面板上的安装按钮转入标准安装流程。

语音包是包含 `manifest.json` 与音频文件（WAV 或 MP3）的目录。`slots` 对象将槽位名映射到包内音频文件。包不必覆盖全部槽位：未覆盖的槽位保留官方原声。使用「VIR: Open Voice Packs Folder」创建并打开语音包目录，放入语音包后执行「VIR: Rescan Voice Packs」即可识别。制作语音包的完整规范见[语音包制作指南](docs/voice-pack-authoring.zh-CN.md)（[English](docs/voice-pack-authoring.md)）。

## 网络访问

选择列表从 GitHub 获取索引仓库：依次尝试 raw 直连地址、jsDelivr 镜像，以及 `vir.packMirrorTemplate` 配置的镜像前缀（如已设置）。语音包下载始终来自包作者本人的仓库，并固定到索引条目记录的提交。每一跳均有独立超时；索引获取失败不阻塞列表展示：本地语音包与直装入口仍然可用。

所有请求遵循编辑器的代理配置（`http.proxy`）。在 GitHub 不可达的网络环境中，可在 VS Code 中设置 `http.proxy`，或将 `vir.packMirrorTemplate` 设为镜像前缀（如 `https://ghproxy.net/`）。镜像是由用户自行选择信任的第三方中转；固定到提交哈希的下载经镜像后逐字节一致，而按分支寻址的索引可能滞后一个镜像缓存窗口。

## 信号开关

替换文件不会自动打开信号。编辑器仅在对应的辅助功能信号设置开启时才播放音效。首启通知会引导先选择语音包，因为信号开关只在有包应用后才有意义。每次成功应用后，结果通知提供两种开关模式：**全开信号**（全部信号设置开启；未覆盖的事件播放官方原声）或 **按语音包来**（已覆盖的设置开启，其余关闭）。**VIR: Enable All Signals** 可在任意时刻执行全开——纯编辑器设置操作，与当前语音包无关；**VIR: Restore Signal Toggles** 将这些设置恢复为先前的值。

## 命令

| 命令 | 功能 |
|---|---|
| VIR: Open Voice Packs Folder | 创建并打开语音包目录。 |
| VIR: Rescan Voice Packs | 重新扫描语音包目录并报告损坏的包。 |
| VIR: Select Voice Pack | 选择生效语音包并立即应用；选择「不启用」还原官方音效。亦可点击状态栏铃铛进入。 |
| VIR: Apply Voice Pack | 按需备份，重算全部槽位，替换文件并校验。未选包时先引导选择。 |
| VIR: Toggle Sound Replacement | 主开关。关闭立即还原官方音效，开启重新铺设所选语音包；编辑器更新遵循开关状态，关闭期间的新版本保持原生。 |
| VIR: Restore Original Sounds | 还原官方文件并逐个校验哈希。 |
| VIR: Open Signal Settings | 跳转到设置页的信号区域。 |
| VIR: Enable All Signals | 开启编辑器的全部信号设置。 |
| VIR: Restore Signal Toggles | 将本扩展开启过的信号设置恢复原值。 |
| VIR: Status | 完整报告：语音包、替换、备份、槽位覆盖、开关。 |
| VIR: Delete Backup | 删除备份本身，需二次确认。 |
| VIR: Identify Sounds | 引导式校准流程，按听感将触发点映射到槽位。 |

## 设置

- `vir.editorInstallPath`：手动指定编辑器安装位置，用于自动检测无法解析的安装。
- `vir.packRegistryRepo`：作为语音包索引的 GitHub 仓库，`owner/repo` 形式。
- `vir.packMirrorTemplate`：可选的 URL 前缀，附加到直连 GitHub 地址之前作为额外镜像跳，用于 GitHub 不可达的网络环境。

## 不受支持的安装形态

扩展会识别并以明确信息拒绝以下形态，不做任何猜测：Microsoft Store 版、Windows 系统级安装（写入将落入 `C:\Program Files`）、macOS（修改应用包会破坏其代码签名）、root 属主的 Linux 安装（deb、rpm、`/opt`），以及只读包格式（snap、flatpak——提权亦无法写入）。请使用用户级安装的官方 VS Code。

## 还原与卸载

- **VIR: Restore Original Sounds** 从备份还原全部文件，并逐个比对备份记录中的哈希。
- 卸载扩展时，卸载钩子自动还原官方文件。
- **VIR: Delete Backup** 删除备份本身。没有备份就没有退路，只能重装编辑器，因此需要两次确认。
